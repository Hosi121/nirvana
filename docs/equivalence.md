# 同値性の契約

正本は入力機械語の振る舞いであり、各段階を検査する中心には小さな低水準IRを置く。
IRインタプリタも仕様に照らして検証する対象で、IR同士の一致だけでは機械語との一致を主張しない。
目標は、明示した前提を満たすすべての対応する初期状態で、観測した振る舞いが等しいこと。
前提や観測対象を、検証を通すために弱めない。

## 現在のIRの実行モデル

- 有限個の初期化済みu64レジスタ。各入力値は任意で、0初期化を正しさの前提としない。
- 加減乗算はmodulo 2^64、比較は0/1、シフト数は63でマスクする。
- 上位乗算は128-bit積の上位64-bit、Selectは選択した側だけを評価する。
- 単一スレッド。メモリはbaseと有限byte列で与えた、一つのゲスト領域。
- little-endianの1/2/4/8-byteアクセス。領域外とu64アドレスの折り返しは明示的なFault。
- 逐次代入。先に成功した書き込みは、同じ命令内の後続処理が失敗しても取り消さない。
- storeはアドレス式、宛先全体の範囲、値の順で評価し、検査と値評価が成功してから書き込む。
- 分岐先は検証済みの閉じたCFG。外部呼び出し、volatile、MMIO、並行実行は未モデル化。

これはchecked guest-memoryの仕様であり、実CPUのページ権限や全例外のモデルではない。
x86の根のRETを関数終了として扱う現在のフロントエンドにも、独立した境界条件が残る。

## 実行結果を失わない

`Program`、`StructuredFunction`、`ReducedFunction` の `run_with_memory` は
`RunReport { status, state }` を返す。

| status | 意味 |
| --- | --- |
| Returned(value) | 正常終了と返り値 |
| Fault(access, address, width) | checked memoryの読み／書き失敗 |
| Suspended | 検査用の命令上限に達した。非停止とは判定しない |

stateにはレジスタ、全ゲストメモリとbase、開始した命令のアドレス列、現在／次に試みる命令位置を保持する。
失敗した命令の前半で完了した副作用も残す。入力レジスタ数の不一致は実行前のAPIエラーとして外側のErrにする。
還元IRのレジスタは拡張された内部値を含むため、元IRとの比較にはreturn-memory契約を使う。
従来の `execute_with_memory` は互換用の射影で、失敗時は従来どおり状態を落としてExecutionErrorを返す。

## バージョン付き観測契約

`observe::Contract` のすべてのプロファイルは、全メモリと正確なモデル内Faultを観測する。
メモリ領域やFaultを無視する設定は用意しない。将来スタックを隠す場合も、非脱出などの根拠が必要。

| ID | 観測対象 | 用途 |
| --- | --- | --- |
| full-ir-state-v1 | 全IRレジスタ、全メモリ、終了結果、命令アドレス列 | 構造化前後の強い回帰検査 |
| return-memory-v1 | 返り値、失敗まで含む全メモリ、終了結果 | 高水準化の具体実行比較 |
| return-memory-trace-v1 | 上記と命令アドレス列 | 現在の還元処理の強い回帰検査 |

命令位置そのものは、読みやすいCの外部観測には含めない。実行時間・内部命令数・ローカル変数名も対象外。
呼び出し規約、保持すべきレジスタ、I/O等は対応する段階で契約を追加する。現在対応済みとは扱わない。
比較には対応する初期状態からの二つのrunを渡す。比較器自体は初期状態の対応を証明しない。

| Comparison | 主張 |
| --- | --- |
| MatchForInput | この対応入力の完了した実行で一致した。全入力の証明ではない |
| Counterexample | この対応入力で契約違反。最初の異なる状態要素を返す |
| Inconclusive | 片方以上がSuspended。成功にも非停止にも数えない |

片方がReturnで他方がSuspendedでも未判定とする。異なる途中状態が最終状態の違いを意味するとは限らないため。
両方のFaultが同じでも、その時点のメモリは比較する。読み失敗と書き失敗は区別する。

## 境界ごとの検証

| 境界 | 現在の証拠と残る範囲 |
| --- | --- |
| 機械語→低水準IR | 命令の算術オラクルとnative fixture比較。形式証明なし |
| 低水準IR→還元IR | メモリ・Fault・境界値をSMTで検査する任意モードを追加。同じCFGの30/33構成をモデル内で採用。未判定時は元IRを保持 |
| CFG→構造化AST | 独立にASTをグラフ化し、元の命令・代入列・両分岐・戻り先を対応検査。全recoverに接続 |
| 表示用IRのレジスタ改名 | [web検査器](definition-webs.md)が構文と全CFG経路のread対応を固定点で検査。入口seedと任意の追加レジスタ初期値を扱い、失敗時は元IRを保持 |
| AST→C | 再コンパイル比較。C出力全体の形式証明なし |

検査器を変換器から分ける。未判定の変換を検証済みへ昇格させない。
Loadのない式を固定幅ビットベクトルとして扱う[変換前後の検査器](pure-expression-verification.md)を実装した。
[メモリ付きブロックの検査器](block-verification.md)は、全CFG境界での遷移対応を確認する。
[構造化ASTの対応検査](structure-verification.md)も別モデルとして実装した。
この検査器は式の構文的一致を要求し、基本のNode ASTまでを扱う。
機械語のリフト、C用のcompact・ループ整形、C出力全体の検証は別の範囲であり未完了。
生成Cでも、元の機械語の定義された挙動をCの未定義動作に落としてはならない。

## 今回塞いだ穴

`store(0, 1); load(bad)` と `store(0, 2); load(bad)` は、従来APIでは同じMemoryAccessエラーになる。
run APIとreturn-memory-v1では、失敗前のbyte 0の違いを反例として取得できる。
この変異例、読み／書きFaultの違い、途中命令の副作用、打ち切り、構造化の失敗時状態を回帰検査する。

設計上の参考: [CompCertの意味保存](https://compcert.org/man/manual001.html)、
[Alive2のtranslation validation](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf)。
両者をNirvanaの実装依存にはしていない。
