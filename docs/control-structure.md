# CFGからの制御構造復元とC生成

## 今回の問いと区切り

既知のCFGに式と代入の意味を付けたとき、返り値・レジスタ状態・命令の実行順序を保ちながら、
分岐を`if/else`へ、自然ループを`while`と`break`・`continue`へ戻せるかを確認します。
後支配、実行可能IR、構造化、C生成、生成Cの実行比較に続き、複数出口と共有末尾へ対応しました。
Rust標準ライブラリのみで実装しています。既存の解析器やコンパイラ基盤は組み込んでいません。

## 出口と後支配

`PostDominators`は実際の終端ブロックを共通の仮想出口へ結び、有限の出口到達経路に対する
後支配集合を固定点反復で求めます。仮想出口は`PostDomNode::Exit`で、実ブロックと区別します。
別々のreturnへ向かい、共通の実ブロックがない分岐の直接後支配者は仮想出口です。

到達可能な各ブロックが実際の終端へ到達できることを、前任辺の逆探索で確認します。
出口に届かないブロックがあれば`NoExitPath`を返し、無限ループに架空の出口を足しません。
出口に届く経路があるループも、実行が必ず停止するとは限りません。この解析は停止の証明ではありません。
未解決の制御フローは、従来と同じく解析エラーです。

この定義と無限領域の扱いは今回の実装の仕様です。LLVMなどと同じ結果になることは要件にしていません。

複数出口の合流点には、出口先すべての最も近い共通後支配者を使います。
ヘッダの直接後支配者はループ内部にある場合があり、ループの後続ブロックとは限りません。
出口先が一つなら、そのブロックをそのまま後続とします。

## 比較のためのIR

`Program`は各命令の元アドレス・長さ・逐次代入・制御移転を持ち、既存のCFG構築へ接続します。
レジスタ番号とレイアウトを生成時に検証します。入口から到達する未解決辺があるIRは実行やC生成へ渡しません。
入力の並びはアドレス順へ正規化します。

値はunsigned 64-bitで、加減乗算は2^64で折り返します。式は純粋で、比較結果も64-bitの0または1です。
シフト量は63とのANDを取ります。代入は記載順に実行し、その後に分岐条件やreturn式を評価します。
これらはIRの定義であり、実CPUの全命令の意味をモデル化したものではありません。
機械語フロントエンドの追加で`Expr::Load`と`Place::Memory`を導入し、checkedなlittle-endianメモリも読み書きします。
元命令のフラグは専用レジスタに展開します。除算と呼び出しは未対応です。

IRインタプリタは命令アドレスを一つずつたどります。終了時に返り値・全レジスタ・
元命令アドレスの列を返します。構造化後の実行器は別にASTをたどり、同じ結果を返します。
式・代入の意味は共有しますが、制御フローを進める方式を分けて比較します。
命令数の上限は元命令の実行ごとに消費するので、制御構造を変えても同じ単位になります。

## 構造化する条件

構造化器は、分岐から直接後支配者までの領域を両側の枝として再帰的に復元します。
共通の合流ブロックは分岐の後へ一度だけ出します。別々のreturnも扱います。
元命令は代入が空でも`Step`ノードとして残し、分岐・ジャンプを含む実行順序を比較できるようにします。

自然ループのヘッダから本体を復元し、内側ループのヘッダへの辺を`continue`、
共通後続への辺を`break`にします。ヘッダ内の代入や条件評価も毎回実行します。
入れ子ループを扱います。終了点のない単純な無限ループも、後支配を使わず復元できます。
出力はまず`while (1)`を使い、元のフラグ計算や条件の位置を失わない形を選んでいます。

## 複数出口と共有末尾

複数の出口からそれぞれ共通後続までの処理を復元し、対応する`break`の前に配置します。
共通後続のブロック自体はループの後へ出します。出口ごとの代入と、共通後続の一度だけの実行を保ちます。
異なるreturnへ至る場合には仮想出口を共通後続とし、returnをループ内の対応する枝に置きます。
入れ子ループの内側に複数の出口がある形も対象です。

出口の処理を復元するときは、現在のループを除いたCFG上の文脈を使います。
外側の`break`や`continue`は対象の深さを持たせ、出口処理を内側ループへ移すときに深さを補正します。
出口処理の中にも別のループがある場合、そのループ内の局所的な転送は補正せず、外側を対象にするものだけを補正します。

共有末尾は静的なコードの複製を許可します。同じ命令を一回の経路上で余分に実行してよいという意味ではありません。
既定では元ブロックの構文木への配置数を最大2に制限し、上限を超えたら構造化全体を中止します。
これにより、ブロックとその中の元命令・式が際限なく複製されることを防ぎます。
`recover_with_copy_limit`で上限を指定でき、1なら複製を禁止します。
`StructureStats`と`COutput::structure_stats`で、一意のブロック数・総配置数・追加コピー数を取得できます。

次の形などは理由付きで失敗を返し、C出力側が元のCFGから`goto`付きの関数を生成します。

- 非可約CFG。
- 複数出口の共通後続を現在の後支配解析で求められない形。
- 設定した静的コピー数の上限を超える形。
- 現在の領域分割では適切なループや後続を割り当てられない経路。
- 後支配情報がなく、分岐の合流を安全に扱えない形。

失敗途中の構文木は使いません。成功時には、入口から到達する全ブロックを扱ったことも確認します。
構造化の成功は可読性の優位を意味しません。別モードの[readable-c.md](readable-c.md)では、
式・ローカル変数への還元と単純な`while`・`do/while`化を追加しています。`for`や変数名の復元は今後の課題です。

## ループをまたぐ脱出

`BreakOuter { levels }`と`ContinueOuter { levels }`を追加しました。`levels: 1`は現在より一つ外側の
ループを対象にします。AST実行器は、ループを一つ抜けるごとに深さを減らし、目的のループで転送を消費します。

Cでは、外側への転送がある関数だけに`nirvana_transfer`と`nirvana_continue`という局所変数を生成します。
内側のループを抜けた直後、次の元命令を実行する前に転送を処理し、必要な深さまで脱出を伝播します。
深さは0に初期化し、対象に着くと0になるので、その後の通常の脱出・継続には影響しません。
元のレジスタ配列は補助フラグの保存先に使いません。

これにより既存の`nonlocal-exit`も`goto`なしで出力できます。3重ループをまたぐ脱出と継続、
外側へ継続した後の通常の内側脱出、別ループを含む出口処理も回帰検査しています。
補助変数と伝播処理が増えるため、`goto`表現に対する可読性の優位はまだ評価していません。

## Cへの変換

レジスタのみのIRでは`emit_c`は`uint64_t nirvana_fn(uint64_t *r)`を生成します。`r`は入出力のレジスタ配列です。
実バイナリの引数や戻り値の型を復元した結果ではありません。
アドレスはコメントに残します。構造化できなかった理由は`COutput::fallback_reason`で取得できます。
メモリを使うIRでは、guestメモリのポインタ・基準アドレス・サイズも引数に追加します。
機械語入力との接続とメモリの仕様は[machine-frontend.md](machine-frontend.md)を参照してください。

式の演算結果は比較も含めて`uint64_t`へキャストし、入れ子の比較が意図せずsigned intの演算に
変わらないようにしています。シフト量のマスクもCへ出力します。
現在は実際のfixture機械語からのIRにも同じ変換と検査を使っています。
任意のCコードや実機械語との一般的な同値性を証明するものではありません。

## 検査と実測結果

構造化とC fixtureを統合した段階では、61テスト、Clippyの警告ゼロ、rustfmtの確認を通過しました。
後続の機械語フロントエンドを含む現在の93テストについては[machine-frontend.md](machine-frontend.md)を参照してください。

以前の4命令4,000通りの検査には、後支配の頂点除去による照合を追加しました。
出口へ到達できない領域の検出も、別の探索で比較します。

演算を追加した4,000通りのIRでも構造化を試し、成功したものについて3入力・各64命令の上限で
返り値、全レジスタ、元命令アドレスの実行順序を比較します。
両方が上限に達した場合は上限の扱いを比較しただけであり、その先の挙動の証拠にはしません。

複数出口・上限付き複製の変更前後を、同じ4,000通りと同じ3入力・64命令上限で比較しました。
構造化成功数は3,805から3,843へ増えました。これはこの小入力集合での対応範囲の差であり、
実バイナリでの復元精度を示す数値ではありません。既定の静的配置数が元ブロック数の2倍以下であることも確認します。
同じ従来の9例では、`goto`へ戻す例が3つから1つへ減りました。
その後のループ間転送への対応では、同じ4,000通りの成功数が3,843から3,859へ増えました。

加えて、固定シードで生成した8命令のCFG 1,024個について、構造化できたものを3入力・128命令上限で比較します。
複数出口の前に必ず通るループ内部のブロック、入れ子の複数出口、ループからの異なるreturn、
コピー数の上限超過、外側への`continue`の誤結合も専用の例で検査します。

元Cのfixtureを追加し、現在は20例×63入力×2最適化設定の2,520ケースで、元Cの実行結果と
手計算の27期待値および設定間の一致を確認します。対応する14例の生成Cは同じ入力で
計1,764ケースを実行し、元C・IRの返り値と最終レジスタ値に一致しました。
使用した`cc`はGCC 13.3.0、設定は`-std=c11 -Wall -Wextra -Werror -pedantic`と`-O0`または`-O2`です。
共有末尾・複数出口・非局所脱出の構造化と、非可約CFG・コピー数の上限超過の`goto`出力を含みます。
3重ループと出口処理内の別ループについても、4モード・8モードを2最適化設定で実行する追加24ケースを比較します。
ネイティブ実行には5秒のタイムアウトを設け、検査用ソースと実行ファイルは終了時に削除します。

これらは有限の入力・実行上限での検査です。一般の同値性の証明、性能の改善、
実バイナリの復元精度、GhidraやIDAとの優劣は主張しません。

C fixtureの内容と生成道具は[fixturesの説明](../tests/fixtures/README.md)を参照してください。
今回の作業分担と統合検証は[作業記録](agent-work/nonlocal-transfers/verification.md)に記録しています。
