# 構造化ASTをグラフへ戻して検査する

`structure_verify` は、CFGの構造化後のASTを独立にグラフ化し、元の命令単位IRと対応付ける。
モデルIDは `structured-flow-v1`。構造化器の支配・後支配・ループ解析、領域構築の関数は呼ばない。
SMTも具体入力も使わず、代入列と条件式をそのまま保持する構造化を対象にする。

## DAGとの関係

現在の構造化器は、支配関係に基づくバックエッジから自然ループを発見し、後支配関係で分岐の合流点を探す。
バックエッジを除いたグラフがDAGになるか、トポロジカル処理で可約性を判定する。
DAGへ縮約したグラフを明示的な中間表現として保持し、その上で全体を構造化する実装ではない。
SCCを一頂点にまとめる方式も使っていない。多重入口の循環は現在gotoへ戻す。

検査器が作るグラフは元の繰り返しを含むため、通常の循環グラフである。
循環のない命令列と、ループの継続・脱出先を別々に確認する。

## 独立したグラフ化

ASTを後ろから処理し、「この構文が終わったら進む先」を引数として渡す。

- Stepは元アドレス・逐次代入列・次のノードを持つ。
- Ifは同じ継続先へ合流する二つの枝と、条件式を持つ。
- Loopは戻り先のアンカーを作り、本体末尾の継続をそのアンカーへ接続する。
- Breakは該当ループの後、Continueは該当ループのアンカーへ接続する。
- Outer転送は構文上のループの深さから直接対象を選ぶ。構造化器が発見したループ番号を再利用しない。
- EvaluateとReturnは評価式を持つ意味のあるノードとして残す。

アンカーによるJumpだけは、値・メモリ・実行経路に影響しない構文上の移動としてたどる。
元のStepを挟まずJumpだけで循環する場合はSilentCycleとして拒否する。
本物の無限ループはStepを通るので、この理由では拒否しない。

## 対応付け

元IRの入口アドレスとASTグラフの入口から、有限個の `(元アドレス, ASTコピーのノード)` の対を調べる。
各対について、次を要求する。

1. 次の意味のあるノードが同じアドレスのStepであり、代入の順序と内容が完全一致する。
2. Next／Jumpなら、その先で同じ次の元命令に到達する。
3. Branchなら同じ条件式を一度評価し、taken／not-takenの両方で同じ次の元命令に到達する。
4. 同じ先へ向かうBranchも評価を省かない。Evaluateまたは両枝が同じ先へ進むIfを許可する。
5. Returnなら同じ返り値の式を評価し、関数を終了する。

最後に、元CFGの静的到達範囲の全命令が対応付けられたことを、構造化器のvisited集合とは独立に確認する。
共有末尾の静的な複製は、複製箇所ごとに検査する。戻り辺は既に調べた対へ到達すればよく、反復回数を制限しない。

式と代入が同じであることを要求するので、各対で同じレジスタ・メモリから同じ処理が始まる。
両方の分岐先を対応付けるため、このモデルは入力を選んだ動的テストとは異なる。
同じ式の評価器を前提に、部分命令のFault、失敗までの副作用、元命令のtrace、実行上限も保持するという設計である。
無限実行についても、元のStepを追加・削除せず、意味のない移動だけの発散を許さない。

これは実装された対応検査であり、検査器自体の正しさを証明支援系で形式証明したものではない。
信頼する部分はASTからの独立したグラフ化、対応検査、共通IRの評価意味である。
同値でも構文が変わった式は拒否するため、式の最適化の検査とは分離する。

## 採否と証拠

`StructuredFunction::recover` は最後に必ず検査器を呼ぶ。失敗なら `StructureError::Validation` を返す。
部分的なASTを出力へ渡さず、C出力側は従来のgoto経路へ戻る。
成功時の `StructuredFunction::evidence()` は、元の命令数・比較したコピー数・復元したグラフのノード数を返す。
資源上限はAST／グラフのノードと比較対100,000、構文の深さ256。上限到達は検証成功として扱わない。

検査対象は基本のNode構文木まで。読みやすいC側のcompact、while/do-whileへの整形、C文字列の出力は別の検証範囲である。
また、機械語デコーダ／リフタの意味の正しさをこの対応検査から主張しない。

## 回帰検査

既存の4命令CFG 4,000通りと、固定シードの8命令CFG 1,024個でrecoverを実行すると、
成功したASTはこの検査を通る。4,000通りでの成功数3,859は維持した。
共有末尾、複数出口、3重ループをまたぐ脱出・継続、出口処理内の別ループも検査する。

専用の変異例では、分岐の左右の交換、条件式の変更、代入の入れ替え、空の元命令の削除、
Faultし得る条件評価の削除／重複、外側ループへの転送の誤結合、return値の変更を拒否する。
元に対応するStepを持たない無限ループや、不正な転送深さも拒否する。
