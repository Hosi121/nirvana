# レジスタ転送から式と変数へ

今回の問いは、同じ機械語と入力を使い、返り値とゲストメモリを保ちながら、フラグや補助レジスタの代入を減らせるかです。
区切りは、新しいC出力モードをCLIから使え、既存の機械語fixtureで実行比較が通ることです。
命令デコーダや構造化の対応範囲を広げる変更とは分けています。

## 二つの出力契約

`--emit c` は従来どおり全レジスタを入出力とする `nirvana_fn` を生成します。
フラグや補助レジスタも観測できる契約なので、最終的な返り値に使われないという理由では代入を消せません。

`--emit readable-c` は `nirvana_readable` を生成します。こちらの観測対象は返り値と**ゲストメモリ全体**です。
必要な入力レジスタを値引数 `arg0, arg1, ...` として受け取り、残る中間値を `v0, v1, ...` として表します。
引数と元レジスタ番号の対応は、出力コメントと `ReadableC.parameters` に記録します。
これは呼び出し規約やソースの引数・型・名前を推定した結果ではありません。

メモリを使う関数には、追加で `uint8_t *memory, uint64_t base, uint64_t size` を渡します。
アドレスは整数のゲストアドレスです。ホストポインタへのキャストや配列アクセスへの置換は行いません。
スタックもゲストメモリの一部なので、未観測だと証明していないスタック書き込みは残ります。

## データフローの還元

1. レジスタの生存性をCFG上の固定点で求めます。根はreturn、分岐条件、メモリ書き込み、範囲外アクセスで停止し得る読み出しです。
2. 基本ブロック内のレジスタ定義を新しい値へ付け替えます。同じ機械レジスタの再利用で、先に計算した値を失わないためです。
3. ブロックをまたぐ値だけを、出口で元のレジスタ用スロットへ渡します。ループや合流点を含め、この段階では全体SSAやphi関数を導入しません。
4. 定数・コピーの伝播、式の簡約、純粋な不要代入の除去を、最大8回反復します。

複雑な式の伝播は利用箇所を制限し、置換後128ノードを超える場合は元の式を使います。
Loadを含む値は伝播しません。使われないLoadも、元の命令位置に残します。
ブロック出口のコピーが元レジスタを上書きする場合、その古い値を読む置換候補を無効にします。
例えば二変数の交換で、先に保存した値を上書き後のレジスタ参照に置換しないためです。

簡約の演算モデルはmodulo 2^64、シフト数は下位6ビット、Selectは選んだ側だけを評価します。
同値式への変換でも、Loadの削除・複製・評価順の変更が起きる規則は適用しません。

## C出力

還元したIRに既存の構造化を適用します。空の機械命令ステップはCの文を必要としません。
先頭に単純な脱出条件があるループは `while`、末尾が継続・脱出の二択なら `do/while` として出します。
末尾条件への変換は、途中のcontinueが条件評価を迂回する場合には使いません。
構造化できない形は、理由とともにgotoへ戻します。

Cの比較結果はint型なので、それを算術や左シフトに使う場合は演算**前**にuint64_tへ昇格させます。
式の優先順位に合わせて括弧を付け、範囲が分からないシフト数は63でマスクします。
メモリ境界検査と上位乗算のヘルパーは、従来のC出力と共用します。

## 検証と残る範囲

GCC 13.3.0、x86_64-linux-gnu、既存fixtureと同じC11・fno-lto・O0/O2で比較しました。
対応する33構成の代入数は合計5,023→668です。個別では `diamond -O2` が22→3、
`arithmetic -O2` が237→6でした。ヘルパーの削除やコンパイラ設定の変更による差ではありません。
通常133テストと別途SMT6テスト、Clippy（警告をエラー扱い）、rustfmtが通過しています。
SMTの範囲は[純粋な式](pure-expression-verification.md)と、
任意モードの[メモリ付きIR還元](block-verification.md)です。
基本の構造化ASTには[独立したグラフの対応検査](structure-verification.md)も適用します。
C用のcompact・ループ整形・C出力全体の検証は未完了です。

- 還元IRと元IRの返り値・全メモリ・命令アドレス列を照合します。命令は空になっても残すため、step limitも比較できます。
- 固定シードの任意CFG、ブロック出口での値交換、ループ、メモリのalias、使われないLoad、遅延評価の例を検査します。
- 既存の20ソース×O0/O2を同じコンパイラ設定で使い、対応する33構成×63入力の元C・元IR・還元IR・再コンパイルCを比較します。
- 再生成Cでは四つの状態ワードに加え、ゲストメモリ全体のダイジェストも照合します。IR間のメモリ比較はバイト列の完全一致です。
- Cの整数昇格、優先順位、シフト数、上位乗算を、境界値の組み合わせで独立に検査します。

型・構造体・ローカルスタック変数の復元、関数間の解析、全体SSA、符号付き比較の高水準な表現は次の課題です。
コンパイラが展開・分岐除去したループなどを元ソースどおりに戻すことも、この段階では主張しません。
