# ELF readerの分担と統合

機械語→IRを通す依頼で、親がx86-64 decoder/lifter・IRメモリ操作・CLI・全体比較を担当し、
サブエージェントが独立コピーでELF readerとそのテストを実装しました。
共有API、型、再配置を解決せず保持することを先に固定し、編集範囲を分けています。

サブエージェントの差分は`src/elf.rs`と`tests/elf.rs`のみです。親がchecked rangeと文字列、
symbolサイズ、関数境界を跨ぐ再配置の扱いを確認して適用し、module公開と機械語lifterへの接続を行いました。

- ELF追加9テスト: 切断、各byteの変異、不正table・string・symbol・再配置、実物diamond/call-chainのO0/O2。
- 統合後93テスト、Clippy警告ゼロ、rustfmt確認。
- 元Cから作った40構成中33構成をIRへ変換し、63入力ずつ計2,079ケースで元C・IR・再コンパイルした生成Cが一致。
- 未対応の7構成は再配置を黙って無視せず、理由付きのエラー。
- 実装はRust標準ライブラリのみ。外部解析器の出力は使用していません。

独立コピーでの検査に加えて、親が共有側で全体の機械語パイプラインを再実行しました。
必要な差分とこの記録を残し、独立コピーは反映を確認して削除します。
