# C fixtureとループ間転送の統合記録

2026-11-16。ユーザーの依頼により、C fixture整備とデコンパイラ本体の改修を並行しました。
親がfixture・native実行検査・生成道具・文書を担当し、サブエージェントが独立コピーで
ループをまたぐ転送を実装しました。共有された実装インターフェースと生成CのABIは固定しました。

サブエージェントから契約の4ファイルに限定したpatchと検査結果を受け取り、親が差分を確認して適用しました。
主な確認点は、移動する出口処理内のループを含めた対象深さの補正、Cの転送深さの初期化と消費、
元レジスタを補助フラグで変更しないこと、コード複製上限の維持です。

統合後に親が実行した検査:

- `cargo test --all-targets -- --nocapture`: 61テスト成功。
- `cargo clippy --all-targets -- -D warnings`: 成功。
- `cargo fmt --all -- --check`: 成功。
- 元C: 20例×63入力×O0/O2の2,520ケース。手計算の期待値27件も確認。
- 元C・IR・生成C: 対応14例×63入力×O0/O2の1,764ケースで一致。
- 追加の複数ループ間転送: 12モード×O0/O2の24ケースと、各命令上限でのtrace比較。
- 同じ4,000 CFG: 構造化成功数は改修前3,843、改修後3,859。
- fixture生成道具: O0/O2の40オブジェクトと実行結果を保存し、manifestのハッシュを確認。
- fixtureのUndefinedBehaviorSanitizer検査: 全20例×63入力の1,260ケース成功。

機械語のデコードとCからIRへの変換は実行していません。fixtureは元Cからコンパイルした
将来の入力と実行結果の正本であり、デコンパイルが成功した証拠ではありません。
作業用の独立コピーは変更の反映を確認して削除し、契約・依存関係・この検証結果を残します。
